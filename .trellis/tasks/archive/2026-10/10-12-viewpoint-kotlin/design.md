# Design: viewpoint-blood-fx-fix in Kotlin

## Boundaries

All Kotlin. Feature package `com.dont39.pz.viewpointbloodfxfix` holds everything hand-written; the glue in
`com.dont39.pz.allinone` is generated by `10-12-ksp-glue`. Only
`src/main/lua/client/Dont39AllInOne_ViewpointBloodFxFix.lua` stays Lua.

## Hooks

- `LiftOffsets.liftBlood` / `restoreBlood` -> enter/exit of `bloodfx.Gpu.render`; `liftGore` / `restoreGore` ->
  `bloodfx.GoreGpu.render`; `AimShift.lower(character: Any?)` (argument 0) / `restore` -> `bloodfx.Aim.target`;
  `ViewpointBloodFxFix.setForce` -> Lua `Dont39AllInOne_setViewpointBloodFxFixForce`. Annotation names per
  `10-12-ksp-glue` design.
- Inlined advice is ordinary Kotlin: the generated advice is inlined into BloodFX's methods (`Advice.to`,
  `PatchEngine.java:551`) and its `kotlin.*` references resolve at render time to the stdlib ZombieBuddyKotlin
  installed in its MAIN phase; load order relative to BloodFX does not matter. Hooked functions must not be
  `private` (the inlined call runs inside BloodFX's class); the processor rejects that.
- Fallback if the KSP spike fails: hand-written `object ViewpointBloodFxFixPatches { @Patch(...) object ... {
  @JvmStatic @Patch.OnEnter fun enter() = ... } }` and an `object ViewpointBloodFxFixLua` with `@LuaMethod` instance
  methods (Kahlua binds global functions to an instance, so no `@JvmStatic` there).

## Kotlin shape

- Built on `zombiebuddy-kotlin-utils` (sibling design): the facade is a `Feature`, helper objects resolve through a
  `Resolver`. Rules below still apply to what remains in the feature.

- Each class becomes an `object`. Package-private Java → `internal`; nothing the advice calls is `private`.
  `Relief` stays file-internal to the module.
- Reflection resolution stays in one initializer per object, recording a problem string instead of throwing
  (`zombiebuddy-patching.md` "Reaching Other Mods"); `Relief` keeps `MethodHandle.invokeExact` (Kotlin supports
  signature-polymorphic calls; check the emitted descriptor matches the `asType` signature — a wrong descriptor
  throws `WrongMethodTypeException` at runtime, so this is a review point).
- Hot path (`LiftOffsets.Saved.lift`, loops): primitive arrays, indexed loops, no boxing, no lambdas/iterators on
  per-frame paths, strings only under `debug()`. Volatile fields via `@Volatile`.
- Log text and `NAME` unchanged (smokeTest greps `viewpoint-blood-fx-fix: `).

## Kotlin-not-ready path (R4)

- `Main.kt` calls `ViewpointBloodFxFix.init()` only after `kotlinProblem()` returns null; otherwise it logs the
  existing not-ready line and the feature stays off.
- The facade gets a `ready` flag set only by `init()`. `active()` returns false while it is unset, before resolving
  anything. Patch entries already call `active()` first, so with Kotlin not ready the inlined advice calls one
  trivial static method and returns.
- The facade object's own initializer must not use stdlib APIs newer than 1.4.10 (no `setOf` etc. in its
  `<clinit>` — e.g. keep the BloodFX allowlist in the method that uses it, or behind the `ready` gate). Its first
  use from a patch must not be able to throw out of the render call.
- Verify with the corrupted-stdlib negative check from the archived kotlin-lib task.

## Build

`viewpoint-blood-fx-fix/build.gradle.kts` applies only the feature convention (`pz-feature`, from `10-12-ksp-glue`);
no Java sources remain.

## Rollback

Single module; revert the module's sources and build script.
